생성형 AI 활용 수집 정보 요약 및 분석

요약은 자료를 짧게 옮기는 일이고, 분석은 그 사실이 내 지원 준비에 어떤 의미인지 생각하는 일입니다. 둘을 섞어 단정하지 마세요.

API 없이 진행하는 방법

  1. 4단계 자료에서 필요한 공개 문단만 골라 자료 A·B와 근거 위치를 붙입니다.
  2. 직접 요약하거나, 원한다면 사용하는 외부 AI에 자료와 요청문을 직접 붙여 넣습니다. 이 웹은 자동 전송하지 않습니다.
  3. 외부 답변을 사용했다면 원문을 별도로 보관하고, 사실·내 해석·추가 질문을 나눠 직접 수정합니다.
  4. 기업의 기술·성과·내 경험을 새로 만들어 넣지 않았는지 6단계에서 주장별로 확인합니다.

외부 서비스에는 개인정보·비공개 자료·회사 기밀을 넣지 마세요. 공개 자료도 필요한 범위만 사용하고 이용 조건을 확인하세요. 원문 링크만 주고 도구가 읽었다고 가정하지 않습니다.

가상 사례 3 · 숫자와 해석 나누기

매출 증가를 사업 전체의 성공으로 확대하지 않기

제공 자료 A: 2025년 가상 사업보고서의 실적표(3쪽). 연결 기준 연간 매출은 2024년 120억 원, 2025년 138억 원. 두 값은 같은 범위와 단위다. 이 표에는 시장 순위가 없다.

근거를 넘은 요약

“업계 1위 기업으로 급성장했고 개발 조직도 크게 확장하고 있다.”

근거를 붙인 정리

사실: 연간 매출이 120억 원에서 138억 원으로 증가했다[자료 A, 3쪽]. 같은 기준으로 계산하면 15% 증가다: (138−120)÷120×100.

해석: 매출 변화와 서비스 운영 업무의 관계를 더 알아볼 수 있다.

추가 질문: 증가 원인과 채용 확대 여부는 자료에 없으므로 별도로 확인한다.

좋아진 점: 확인 가능한 값·계산·의견을 구분합니다. 매출 증가만으로 순위나 채용 확대를 결론 내리지 않습니다.

내 기록에 적용하기 → 내 요약의 ‘빠르게’, ‘최고’, ‘확대’라는 표현에 각각 근거가 있나요?

가상 사례 4 · 직무와 내 경험 연결하기

공고의 요구를 내 성과로 바꿔 쓰지 않기

자료 B: 가상 공고 ‘주문 API 개발·운영, SQL 데이터 처리’. 자료 C: 내 가상 프로젝트 기록 ‘주문 생성·조회 API 구현, SQL 쿼리 작성’. 성능 개선 수치는 없다.

경험을 부풀린 연결

“회사에서 필요한 대규모 주문 시스템을 운영했고 성능을 40% 개선했다.”

실제 경험 안에서 연결

사실: 공고에 API·SQL 업무가 있고[자료 B], 내 기록에도 주문 API 구현·SQL 작성 경험이 있다[자료 C].

해석: 구현 경험은 연결 가능하지만 실제 서비스 운영 경험을 증명한 것은 아니다.

추가 질문: 내 역할을 보여줄 코드·명세서와 운영 관련 요구를 더 확인한다. 확인되지 않은 수치는 쓰지 않는다.

좋아진 점: 연결점뿐 아니라 부족한 근거도 보입니다. 이 단계의 메모를 곧바로 완성 자소서로 취급하지 않습니다.

내 기록에 적용하기 → ‘공고에 쓰인 일’과 ‘내가 실제로 한 일’이 문장에서 섞이지 않았나요?

정보 정확성 확인 및 검증

출처 링크가 있다고 검증이 끝난 것은 아닙니다. 그 원문이 내가 쓰려는 문장 전체를 실제로 뒷받침하는지 확인하세요.

문장마다 이 순서로 확인하세요

  1. “해외 매출이 늘고 채용도 확대됐다”처럼 주장이 둘이면 나눕니다.
  2. 출처를 직접 열어 해당 표·문단이 있는지 확인합니다. 열지 못한 자료는 ‘미확인’입니다.
  3. 같은 회사·기간·단위·연결/별도 범위인지, 계획과 실제 실적을 구분했는지 봅니다.
  4. 공식 자료라도 정정·갱신 여부와 작성 시점을 확인합니다. 자료끼리 다르면 억지로 합치지 않고 차이를 기록합니다.
  5. 확인됨 / 수정 후 확인 / 미확인 중 하나를 직접 선택하고, 실제 사용할 문장 또는 제외 이유를 남깁니다.

가상 사례 5 · 기간·단위·범위 맞추기

숫자가 맞아 보여도 비교 기준이 다를 수 있습니다

확인할 주장

“매출이 120억 원에서 1,380억 원으로 늘었다.”

두 번째 표는 ‘백만 원’ 단위의 13,800이고 별도 기준 상반기 값이다.

수정 후 확인

13,800백만 원은 138억 원이다. 그러나 연간 연결 120억 원과 별도 상반기 138억 원을 바로 비교하지 않는다.

동일 기준의 가상 실적표 A를 확보해 연간 연결 120억 원→138억 원, 증가율 15%로 다시 기록한다.

최종 문장: “자료 A의 동일 기준 연간 연결 매출은 2024년 120억 원에서 2025년 138억 원으로 증가했다[3쪽].”

다음 행동 → 같은 기준의 원문을 확보하지 못했다면 증가율은 쓰지 않고 비교 불가로 남깁니다.

가상 사례 6 · 출처에 없는 기술 이름

자료에 없다는 것과 사용하지 않는다는 것은 다릅니다

확인할 주장

“다온테크는 Kubernetes 기반으로 모든 서비스를 운영한다.”

제공한 공고에는 ‘주문 API 개발, SQL 활용’만 적혀 있다.

미확인 · 해당 주장 제외

이 공고로는 Kubernetes 사용 여부나 전체 운영 범위를 알 수 없다. ‘사용하지 않는다’로 반대로 단정하는 것도 피한다.

직접 확인한 공고 요구만 남기고, 기술 스택은 회사의 공개 기술 자료 등에서 추가 확인한다.

최종 문장: “이 공고에서 확인한 담당 업무는 주문 API 개발과 SQL 활용이다[자료 B, 담당 업무].”

다음 행동 → 근거를 못 찾으면 자신감 있는 표현으로 바꾸지 말고 ‘미확인’ 그대로 남깁니다.

가상 사례 7 · 계획과 실적 구분

“추진 예정”을 “이미 달성”으로 바꾸지 않기

확인할 주장

“모아서비스는 해외 서비스를 성공적으로 출시했다.”

가상 IR 자료에는 ‘2026년 하반기 해외 서비스 출시 추진’이라고만 적혀 있다.

표현 수정 · 실제 출시는 미확인

자료가 발표한 계획과 지금 달성한 실적을 나눈다. 자료의 발행일 이후 진행 상황을 확인하지 못했다면 성공 여부도 쓸 수 없다.

계획을 설명하는 문장만 사용하고 실제 출시 여부는 별도 검증 대상으로 남긴다.

최종 문장: “발행일 2026-04-01의 가상 IR 자료에는 하반기 해외 서비스 출시를 추진한다는 계획이 있다[자료 D, 5쪽]. 실제 출시 여부는 미확인이다.”

다음 행동 → 지원 직전에 후속 발표를 확인하고, 기준일 없이 ‘현재’라는 말을 붙이지 않습니다.

주장별 검증 카드 · 입력칸 5개 제안

읽기 전용 예시

실제 구현 시 주장별 카드를 추가하는 구조입니다. ‘미확인’ 카드도 보존하지만 지원 문서용 확인 문장과 분리합니다. 웹이 진위나 검증 상태를 자동 판정하지 않습니다.

여러 주장을 한 카드에 묶지 말고 원래 문장을 남깁니다.

자료명·실제 URL·문단·확인일을 적습니다. 원문을 못 열었으면 그대로 표시합니다.

회사·기간·단위·범위·정정 여부 중 해당 항목을 확인합니다. 해당 없음과 미확인은 다릅니다.

구현 시 상태 선택(확인됨 / 수정 후 확인 / 미확인)과 이유 입력으로 나눕니다.

확인된 표현으로 고치거나 제외합니다. 추가 조사가 필요하면 무엇을 볼지 적습니다.

이 단계에서 남길 결과

원문으로 뒷받침한 문장과 미확인·제외한 주장을 나눈 검증 기록. 미확인 카드가 있어도 조사 기록은 남기되, 확인된 문장으로 합치지 않습니다. 이후 7단계 채용 공고 확인으로 이어갑니다.
