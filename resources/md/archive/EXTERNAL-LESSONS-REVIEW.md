# 외부 실습 3단계 — 반영 전 검토안

> 이 문서는 해당 작업 시점의 기록입니다. 현재 구현 상태와 남은 작업은 [문서 목차](../README.md)를 기준으로 확인하세요.

현재 상태: **과거 미반영 대체안 — 2026-10-17 재개 요청 후 원문 도구로 구현 완료**. 최신 내용은 [추가 구현·검증 보고서](../ai/ai-external-implementation.md)를 확인하세요. 아래 도구 선택은 채택하지 않았습니다.

이하 보류 당시의 기록입니다: 별도 재개 요청 전에는 구현하거나 도구 선택을 승인된 것으로 취급하지 않습니다. 이 파일은 웹 본문에 반영되지 않은 구성안입니다. 캡처 원문의 도구·사용법을 재현한 것이 아니며, 아래 사례는 새로 작성한 학습용 가상 예시입니다.

## 선택할 도구와 단계의 목적

| 단계 | 제안 도구 | 실습 후 남길 결과 |
| --- | --- | --- |
| 나만의 스크립트 | ChatGPT 텍스트 대화 | 자기소개 또는 프로젝트 설명 원고, 말하기용 핵심어 |
| 정량적 지표와 차트 | Google Sheets | 근거와 단위가 있는 비교표, 차트, 한 문장 해석 |
| 모의 면접 | ChatGPT 음성 대화 | 실제 답변에서 부족했던 근거와 다시 연습할 질문 |

여기서 ‘스크립트’는 취업 준비 맥락의 말하기 원고로 해석했습니다. 원문이 자동화 코드 등 다른 뜻이라면 해당 단계는 수정해야 합니다.

각 화면은 준비 자료 → 외부 도구에서 실행할 순서 → 풍부한 예시 → 완료 기준 → 선택적 실습 메모 순서로 구성합니다. 웹 자체에서 음성 면접이나 차트 생성을 실행하는 것으로 표시하지 않습니다.

## 4. 나만의 스크립트를 완성하고 싶다면?

### 준비

직무, 전달할 핵심 메시지, 실제 경험 한 가지, 내가 직접 한 행동, 확인한 결과를 준비합니다. 앞 단계에서 만든 지침 프롬프트와 검토한 문장을 사용할 수 있습니다.

### 실행 순서

1. ChatGPT 새 대화에 자신의 상황과 실제 경험을 넣습니다.
2. 자기소개 또는 프로젝트 설명 중 만들 원고의 목적을 정합니다.
3. 개요를 먼저 받아 사실과 강조점을 확인합니다.
4. 확인한 개요를 말하기 쉬운 문장으로 바꾸도록 요청합니다.
5. 소리 내어 읽고 직접 시간을 재며 문장을 줄입니다. 글자 수만으로 발화 시간을 단정하지 않습니다.
6. 최종 원고와 암기용 핵심어를 따로 보관합니다.

### 예시 A — 자기소개 원고

가상 사실: 신입 백엔드 지원자. 팀 프로젝트에서 담당 API의 오류 응답을 정리하고 프론트엔드 담당자와 공통 형식을 합의했습니다. 이후 담당 API를 수정하고 연동 테스트를 했습니다. 개선율을 측정하지 않았습니다.

부족한 요청: “1분 자기소개를 멋있게 써줘.”

개선 요청:

> 아래 실제 경험만 사용해 신입 백엔드 직무 자기소개 개요를 만들어 주세요. 핵심 강점 한 문장, 그 강점을 보여줄 직접 행동, 지원 직무와의 연결 순서로 정리해 주세요. 확인되지 않은 성과나 기술은 추가하지 마세요. 개요를 확인한 뒤 말하기 원고로 다듬겠습니다. 실제 소요 시간은 제가 읽어보고 조정하겠습니다.

원고 예시:

> 저는 협업 과정의 혼선을 구체적인 기준으로 정리하는 백엔드 개발자가 되고 싶습니다. 팀 프로젝트에서 API별 오류 응답이 달라 화면 연동에 혼선이 생겼을 때, 담당 API의 응답을 문서로 정리했습니다. 프론트엔드 담당자와 공통 형식을 합의한 뒤 담당 API를 수정하고 연동 테스트를 진행했습니다. 이 경험을 바탕으로 담당 기능뿐 아니라 함께 사용하는 인터페이스까지 설명할 수 있는 개발자로 일하고 싶습니다.

핵심어: 응답 형식 혼선 → 문서 정리 → 형식 합의 → 담당 API 수정 → 연동 확인.

개선 이유: 막연한 강점 대신 실제 행동을 사용하고, 글의 목적과 순서를 정합니다. 예시 원고는 정확히 1분 분량이라고 보장하지 않습니다.

### 예시 B — 프로젝트 설명

가상 사실: React 검색 화면 담당. 입력마다 검색 요청이 발생해 디바운스를 적용했습니다. 개발 환경의 네트워크 패널로 요청 시점 변화를 확인했지만 운영 성능 개선율은 측정하지 않았습니다.

설명 구조: 맡은 화면 → 관찰한 문제 → 적용한 방법 → 확인 방법 → 남은 한계.

후속 요청:

> 이 원고에서 제가 구현하지 않은 내용과 근거가 없는 효과가 추가됐는지 확인해 주세요. 기술 용어를 나열한 문장은 직접 한 행동을 설명하는 문장으로 바꿔 주세요. 핵심어 다섯 개도 별도로 정리해 주세요.

완료 기준: 사실 확인, 직접 읽어본 시간, 자기 말투로 수정, 원고 없이 핵심어로 설명하기.

사용법 참고: [OpenAI 공식 프롬프팅 문서](https://learn.chatgpt.com/docs/prompting). 실습 예시는 이 웹을 위해 별도로 작성했습니다.

## 5. 정량적 성과 지표와 직관적인 차트가 필요하다면?

### 준비

실제로 기록한 값과 측정 조건부터 확인합니다. 값이 없다면 성과 수치를 만드는 대신, 무엇을 어떻게 측정할지 적습니다. 각 값에는 단위, 기간 또는 테스트 조건, 자료 출처를 붙입니다.

### 실행 순서

1. Google Sheets에 비교 대상과 값을 입력합니다. 값과 단위·조건이 섞이지 않도록 열을 나눕니다.
2. 비교 조건이 같은지 확인합니다. 서로 다른 조건의 결과는 직접적인 개선율로 묶지 않습니다.
3. 차트에 포함할 라벨과 숫자 셀을 선택하고 ‘삽입 → 차트’를 사용합니다.
4. 전후 비교에는 막대·열 차트, 시간 흐름에는 선 차트가 적절한지 검토합니다.
5. 제목과 축에 측정 대상과 단위를 명시합니다.
6. 차트를 설명하는 한 문장과, 그 수치가 말해주지 않는 한계를 적습니다.

### 예시 A — 처리 시간 비교

학습용 가상 데이터: 동일한 컴퓨터와 동일한 입력 자료에서 같은 작업을 5회씩 실행한 처리 시간(초).

| 실행 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| 1 | 10 | 6 |
| 2 | 12 | 7 |
| 3 | 11 | 6 |
| 4 | 10 | 5 |
| 5 | 12 | 6 |

변경 전 평균: 11초. 변경 후 평균: 6초. 감소율: (11−6)/11×100 ≈ 45.5%.

차트용 표는 ‘변경 전 11초 / 변경 후 6초’로 분리합니다. 제목은 ‘동일 조건 5회 실행 평균 처리 시간’으로 하고, 단위는 초로 표시합니다. 비교 막대의 기준 축은 0부터 시작합니다.

부족한 표현: “전체 시스템 성능이 45.5% 향상됐습니다.”

개선 표현: “동일 조건에서 각 5회 측정한 해당 작업의 평균 처리 시간이 11초에서 6초로 감소했습니다. 운영 환경의 효과는 별도 검증이 필요합니다.”

개선 이유: 측정한 작업과 조건, 반복 횟수를 드러내고 평균 시간의 감소를 전체 성능 향상으로 일반화하지 않습니다.

### 예시 B — 비율과 퍼센트포인트 구분

가상 테스트: 변경 전 40건 중 성공 30건(75%), 변경 후 40건 중 성공 36건(90%). 같은 테스트 묶음을 같은 성공 기준으로 평가했다고 가정합니다.

- 성공률 차이: 90%−75% = 15퍼센트포인트.
- 기존 성공률 대비 상대 증가율: (90−75)/75×100 = 20%.
- 설명 예시: “동일한 40개 테스트 기준에서 성공률이 75%에서 90%로, 15퍼센트포인트 높아졌습니다.”

‘15% 증가’와 ‘15퍼센트포인트 증가’를 혼용하지 않도록 합니다. 실제 측정 자료가 없다면 이 수치를 자신의 성과로 사용하지 않습니다.

완료 기준: 원자료 확인, 같은 비교 조건, 단위와 출처 표시, 수식 검산, 차트 범위 확인, 한계 설명.

사용법 참고: [Google Sheets 공식 차트 도움말](https://support.google.com/docs/answer/63824?hl=ko). 수치와 해석 예시는 별도로 작성한 가상 데이터입니다.

## 6. 모의 면접을 제대로 연습해 보고 싶다면?

### 준비

지원 직무, 채용 공고에서 중요한 요구 사항, 검토한 자기소개서나 프로젝트 설명, 연습할 질문 유형을 준비합니다. 처음에는 질문 3개로 범위를 좁힙니다.

### 실행 순서

1. ChatGPT에 자료와 연습 지침을 제공해 새 대화를 준비합니다.
2. 음성 대화가 지원되는 환경에서는 음성 대화를 시작하고 마이크 접근을 허용합니다. 기능 제공 여부는 계정·플랜·환경에 따라 다를 수 있습니다.
3. 한 번에 질문 하나씩 받고, 답변이 끝난 후 후속 질문을 요청합니다.
4. 질문 3개 뒤 피드백을 요청합니다. 실제 답변에서 근거가 부족한 부분을 구체적으로 짚도록 합니다.
5. 가장 부족했던 답변 하나를 보완하고 같은 질문에 다시 답합니다.
6. 원고 전체를 외우기보다 핵심 행동·판단·결과를 설명할 수 있는지 확인합니다.

음성 대화를 사용할 수 없으면 같은 지침으로 텍스트 질문을 받고 소리 내어 답한 뒤, 답변 요지를 입력하는 방식으로 연습할 수 있습니다. 음성 받아쓰기는 실시간 음성 대화와 다른 기능입니다.

### 시작 요청 예시

> 신입 프론트엔드 개발자 면접을 연습하겠습니다. 아래 프로젝트 기록에 근거해 한 번에 질문 하나만 해주세요. 제가 답변을 마쳤다고 말하기 전에는 다음 질문을 하지 마세요. 질문 3개가 끝나면 ‘구체적으로 설명한 부분 / 근거가 부족한 부분 / 다시 연습할 질문’을 정리해 주세요. 실제 채용 합격 가능성은 점수로 단정하지 마세요. 기록에 없는 기술을 사용했다고 가정하지 마세요.

### 예시 A — 기술 선택

가상 기록: React 검색 화면에 디바운스를 적용하고 네트워크 패널로 요청 발생 시점을 확인했습니다.

질문: “디바운스를 적용한 이유는 무엇인가요?”

부족한 답변: “많이 쓰는 방식이고 성능이 좋아지기 때문입니다.”

개선 답변: “입력할 때마다 요청이 발생하는 것을 보고, 입력이 잠시 멈춘 뒤 요청하도록 디바운스를 적용했습니다. 개발 환경에서 요청 발생 시점이 바뀌는 것은 확인했지만, 실제 사용자 환경의 효과는 측정하지 않았습니다.”

후속 질문: “입력이 끝난 뒤 기다리는 시간 때문에 화면 반응이 늦어지는 문제는 어떻게 확인했나요?”

보완 행동: 확인하지 않았다면 그렇게 말하고, 추가로 비교할 조건과 관찰할 값을 정리합니다.

### 예시 B — 협업에서 내 역할

질문: “API 응답 형식을 합의할 때 본인이 직접 한 일은 무엇인가요?”

부족한 답변: “팀원들과 소통을 많이 해서 잘 해결했습니다.”

개선 방향: 비교한 응답 사례, 본인이 만든 문서, 제안한 규칙, 합의 후 직접 수정한 범위를 실제 사실로 설명합니다. 기록이 없는 구체적 규칙을 예시라고 해서 자신의 경험으로 추가하지 않습니다.

완료 기준: 질문 3개에 직접 답변, 근거가 부족했던 답변 1개 선택, 사실 보완, 같은 질문 재답변.

사용법 참고: [OpenAI 공식 음성 안내](https://learn.chatgpt.com/docs/features/voice). 공식 문서는 제품 동작의 근거이며, 면접 구성과 예시는 별도 제안입니다.
