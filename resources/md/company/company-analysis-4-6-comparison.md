## 5단계: 종합 기업 분석

| 원문 내용 | 현재 검토안 | 수정 제안 |
| --- | --- | --- |
| **10쪽, 목적과 자료.** 자소서·면접에 쓸 기업 정보를 정리. 사업보고서·증권사 리포트에 공식 뉴스룸·대표 신년사·최근 주요 언론 보도를 더해 비즈니스 모델·주력 사업·미래 신사업·SWOT을 종합 분석하도록 요청 | 제공한 자료만 사용해 사실·해석·추가 질문으로 나누는 방식. 기업 전체 분석보다 개별 문장과 직무 경험 연결에 초점 | 자료 목록과 분석 목적을 원문에 맞게 확대. 기본은 사용자가 확보한 자료 분석으로 두고, 검색 가능한 외부 도구를 사용하는 경우 추가 조사할 자료·기간·출처를 별도로 지정하도록 안내 |
| **10쪽, 출력 구조.** ① 기업 개요·실적 ② 시장 분석 ③ 사업 동향 ④ 기업 문화. 수치·키워드·불릿 포인트를 권장하고 분량 제한은 두지 않음. **12쪽 사례에는 ⑤ 종합 SWOT 분석도 보임** | 사실 / 내 해석 / 추가 질문 구조만 제시. 위 분석 영역과 SWOT이 없음 | 결과를 5개 분석 영역으로 구성하고, 각 영역 안에서 사실·출처·해석·미확인을 나누도록 결합. SWOT은 10쪽의 분석 목적과 12쪽 사례를 근거로 추가하는 항목이라고 설명 |
| **11쪽, 실행 흐름.** 앞서 만든 기업 분석 지침과 미리 모은 공시·투자 리포트를 함께 전달. Claude의 프로젝트 지침 설정과 Gemini에 자료를 전달하는 화면을 예시로 제시 | 공개 문단과 요청문을 외부 AI에 직접 붙여 넣는 일반적인 흐름만 있음 | `지침 준비 → 자료 전달 → 분석 결과 읽기 → 추가 질문 → 검증` 순서를 보강. 도구 이름은 원문의 예시로 소개하고 특정 메뉴나 현재 기능을 보장하지 않음. 이 웹에서는 요청문 작성·복사까지 지원하는 기존 방식과 연결 |
| **11쪽, 추가 요청 예시 4개.** 산업 내 위치·강점, 집중 사업·신사업·투자 분야, 경쟁사 대비 차별점, 근무 환경·IT 업계 기업 문화 차별점 | ‘미확인 주장·다음 질문’ 칸은 있으나 원문의 추가 요청 예시는 없음 | 네 가지 질문 유형을 선택 가능한 작성 도움말로 추가. 비교 기업·기간·자료를 함께 지정하고 근거가 없는 항목은 미확인으로 남기는 예시를 작성 |
| **12쪽, 현대오토에버 사례.** 자료 파일을 지침과 함께 전달한 화면, 기업 개요·수익 구조와 종합 SWOT의 일부를 보여 줌. 중간 내용은 ‘중략’ 표시. SWOT 표는 강점·약점 일부가 보임 | 가상 기업의 매출 증가율, API·SQL 경험 연결 사례를 사용 | ‘원문은 현대오토에버 사례로 분석 구조를 설명한다’는 맥락을 소개. 실습용 사례는 기존 가상 기업을 활용해 5개 영역의 연결을 보여 줌. 원문에서 생략된 결과나 사례의 실제 수치를 검증된 기업 정보로 복원하지 않음 |
| **10–12쪽은 프롬프트와 결과 사례 중심.** 현재 메모 양식 5칸과 비교 사례는 별도 보완안 | 자료·목적, 초안, 사실, 해석·직무 연결, 미확인 질문을 각각 작성 | 초안 보관과 직접 수정 구조를 유지. ‘사실’과 ‘해석’에 분석 영역을 표시하고 기업 전체 분석을 먼저 수행하도록 도움말을 수정. 경험 연결은 선택적인 활용 메모로 배치 |

**제안하는 5단계 결과물:** 기업 개요·실적 / 시장 / 사업 동향 / 기업 문화 / SWOT을 포함하며, 각 영역의 근거와 미확인 항목을 구분한 분석 메모.

아래는 원문에 맞춰 다시 구성한 **수정 제안 프롬프트**입니다. 원문의 전사본이 아니며, 근거 표시와 미확인 처리 규칙을 보완했습니다.

## 6단계: 정확성 확인

| 원문 내용 | 현재 검토안 | 수정 제안 |
| --- | --- | --- |

**제안하는 6단계 결과물:** 확인한 주장·근거·판정 이유·최종 문장을 남긴 검증 기록과 아직 확인하지 못한 질문 목록.

수정 제안 요청문은 다음과 같습니다.

```text

주장별로 다음을 정리해 주세요.
- 원래 주장
- 대조한 자료의 제목·URL 또는 파일 위치·발행일·근거 위치
- 근거가 뒷받침하는 내용과 충돌하거나 빠진 내용
- 확인 가능 / 오류 확인 / 미확인 중 판단과 이유
- 수정 제안 및 추가로 확인할 자료

확인하지 못한 것을 틀렸다고 단정하지 마세요.
접근하지 못한 자료는 읽었다고 하지 말고, 검색 기능이 없으면 알려 주세요.
이 답변은 검토 보조 자료로 사용하며, 최종 문장은 제가 원문과 직접 대조하겠습니다.
```

## 검토 후 제안하는 구현 순서

한 번에 한 부분씩 원문 확인과 작업을 진행합니다. 이번에 읽은 페이지는 다시 불러오지 않고, 추가 확인이 필요한 페이지만 한 장씩 확인합니다.

1. **4단계부터 반영:** DART의 읽을 항목, DartPoint AI, 한경컨센서스, 비상장기업 조사 경로를 보강. KIND와 가상 사례는 보완 내용으로 표시. 자료 카드 작성·저장·복사 연결을 점검한 뒤 다음 단계로 이동.
2. **5단계 반영:** 5개 분석 영역과 추가 질문 4종을 포함하도록 설명·프롬프트·작성 도움말을 수정. 사용자가 편집한 지침과 원래 받은 답변을 보존하는 흐름을 확인.
3. **6단계 반영:** 공식 홈페이지·최신 기사 대조, 누락 정보 점검, 검증 요청문을 추가. 미확인과 오류를 구분하며 사용자가 최종 판단하는 기록 방식을 연결.

이 순서는 검토를 위한 후속 제안입니다. 이번 작업 결과는 원문 대조표와 수정안이며, 워크북 콘텐츠나 작성·저장 기능에 반영한 상태는 아닙니다.
