# 자기소개서 2단계 — 직무와 어울리는 나의 경험 및 핵심 키워드 탐색

> 이 문서는 해당 작업 시점의 기록입니다. 현재 구현 상태와 남은 작업은 [문서 목차](../README.md)를 기준으로 확인하세요.

상태: 로컬 구현·검증 완료, 사용자 검토 대기.

## 이번에 한 작업

- 자기소개서 2단계를 활성화했다. 전체 45개 중 15개를 사용할 수 있으며, 자기소개서 3단계 이후와 AI 외부 안내 3개는 기존 보류 상태다.
- 설명을 문항·직무 기준 정리 → 후보 비교 → 대표 경험 선택·설명 전략 → 키워드·행동·직무 기여 → 필요한 추가 요청 순서로 구성했다.
- 필수 작성칸은 기존 question / candidates / selected / keywords 네 키를 유지했다. 기존 초안·수동 또는 의도적으로 비운 요청문·AI 답변 원문·자유 메모를 보존한다.
- 가상 백엔드 직무의 SQL 오류 수정 경험과 동아리 안내문 개선 경험을 비교해 선택·보류 이유, 설명 전략, 키워드와 기여 계획을 보여준다. 예시는 자동으로 입력하지 않는다.
- 경험이 하나뿐이면 범위·한계를, 아직 후보나 근거가 부족하면 선택 보류 이유·찾아볼 기록·다음 행동을 남길 수 있다. 완료 표시는 작성 및 사용자 확인 여부이며 경험이나 직무 적합성을 자동 판정하지 않는다.
- 앞 단계 문항 분석과 기업 자기분석을 읽기 전용으로 참고한다. 네 필수 항목과 최종 확인만으로 완료할 수 있으며 AI 사용은 선택이다.
- 요청문은 제공한 문항·후보·선택 내용만 조합한다. 초기 후보 비교와 선택 후 키워드 탐색을 지원한다. AI 원문·최종 키워드와 예시를 자동으로 요청문에 넣지 않는다.
- 공개 근거와 해석, 팀 성과와 내 기여, 과거 결과와 미래 기여 계획을 구분한다. 측정 조건·단위·기간·기록이 없는 성과 수치를 만들지 않도록 안내한다.

## 자료 확인 기록

로컬 `resources/pdf/3-essay-source.pdf` 5–9쪽을 렌더링해 시각 확인했다. 5쪽의 후보 2~3개 비교·대표 경험 선택·설명 전략, 6쪽의 핵심 키워드·강점·성과·직무 연결 추가 요청, 7–9쪽의 사례 흐름을 반영했다. 9쪽의 예시 성과 수치는 본인 성과로 대체해야 한다는 주의점을 실제 측정 근거 확인으로 구체화했다. 실제 기업 사례의 기술·성과·기업 주장은 학습자의 사실로 옮기지 않고 별도의 가상 사례를 구성했다. OCR은 사용할 수 없어 페이지 이미지로 확인했으며, 제작 설명·페이지 번호는 사용자 학습 화면에 표시하지 않는다.

## 검증 상태

- 자동 검사 228개 통과, 실패 0개. 새 단계의 입력·완료 조건, 후보 비교와 후속 요청, 기존 기록 보존, 내보내기·선택 복원, 검색·진행 상태, 한글 조합·완료 해제 등 10개 검사 추가. 기존 학습 가능 범위 기대값은 15개로 갱신했다.
- JavaScript 17개 파일 문법 검사 통과.
- 독립 Chromium 1280×900 / 390×844에서 필수 항목, 빈 입력 완료 차단, 최종 확인 후 완료, 수정 시 확인·완료 해제, 재조합 취소·동의, 수동·빈 요청문 및 AI 원문 보존, 새로고침 복원 확인.
- 합성 한글 조합 이벤트 중 저장·미리보기 보류, 조합 종료 후 갱신과 입력 요소 유지 확인.
- 실제 JSON·Markdown 다운로드 내용, 선택 복원 기본값, 선택한 단계만 복원, 다른 단계·보류 초안 보존, 직전 보호본 다운로드 내용 확인.
- 설명·예시·작성 탭의 가로 넘침, 중복 ID, 페이지 스크립트 오류 없음. 데스크톱·모바일 작성 화면 시각 확인.
- 사용자 브라우저 저장소에 접근하지 않고 독립 테스트 저장소를 사용했다. 실제 운영체제 한글 키보드 입력, 외부 AI 답변 품질, 개인 경험의 사실 여부는 자동 검증하지 않는다.
