## 수정 범위

기업 분석 10개, 자기소개서 10개, IT 포트폴리오 10개, 면접 9개, 총 39개 단계의 핵심 설명과 요청문·사례를 다시 작성했다. 제공된 4개 PDF의 112쪽 OCR 추출문을 다시 읽고 핵심 표·화면은 기존 렌더링 이미지로 대조했다. 현재 PDF 해시가 렌더링 대상과 같은지 확인했다. 112쪽 전체의 작은 화면 글씨를 모두 새로 육안 판독한 것은 아니다.

- 기업 분석: AI의 보조 역할, 도구별 활용, 고정·가변 지침, DART·DartPoint·리포트·비상장 조사, 5영역 분석과 추가 질문, 사실 확인, 공고·직무·자기 분석, 지원 동기·포부 연결로 재정리했다. KIND 등 원문 밖의 보충 경로를 핵심 설명에서 제외했다.
- 자기소개서: 문항 분석의 네 항목, 대표 경험 선택과 추가 키워드 질문, STAR·KPI·FAB, 문항별 구성과 자가 점검, 첨삭의 핵심 기준, 내용·형식 최종 점검을 복원했다.
- IT 포트폴리오: 역량 3개 우선순위, 캐치프레이즈 세 방향, Main·Sub와 숙련도, 개요·역할·기술 선택·STAR·전후 성과·KPT, 양식별 장단점, Canva 10장 구성, Notion 블록 구성으로 맞췄다.
- 면접: 기술·CS 3개와 프로젝트 3개 질문, 질문 유형별 답변 구조, 직무·임원 평가의 다섯 기준, 임원 질문 네 관점, 음성 2~3개 질문 후 종합 평가, 뷰인터 영상·리포트, 싸피엔스 설정·질문·피드백·재연습 흐름을 재작성했다.

학습 화면의 외부 링크를 제거하고, 출처·주소·확인일을 반복 요구하던 도움말·예시·새 요청문을 정리했다. 서비스와 조사 도구 이름, 기업 공식 정보와 실제 경험을 확인하는 학습 내용은 유지한다. 기업 자료 카드의 주소·날짜 입력과 채용 공고의 별도 출처 입력은 화면·완료 조건·작성 수 집계에서 제외했다.

## 구현과 저장 호환성

`dist/assets/js/pdf-content.js`를 39개 단계의 설명·요청문·사례와 페이지 대응 정보의 기준으로 사용한다. 공통 렌더러는 핵심 설명·예시에 적용하고 기존 작성·저장·백업 양식은 연결해 유지한다. 입력 안내와 펼침 예시도 수정한 필드 정의를 사용한다.

기존 저장 키와 백업 스키마는 유지한다. 숨긴 주소·날짜 값, 이전 수동 요청문, 의도적으로 비워 둔 요청문, 원문·수정본·자유 메모를 자동 삭제하거나 변환하지 않는다. 기존 사용자가 저장한 주소·출처는 전체 기록·백업에 남을 수 있다. 새 작성 화면에서 입력하도록 요구하지 않는다.

## 원문 그대로 일반화하지 않은 부분

원문에 없는 성과를 사용자 경험에 추가하지 않으며 TTL 하나로 정합성을 보장한다는 표현은 사용하지 않는다. 숙련도 근거가 없으면 초급으로 추정하지 않고 미확인으로 둔다. 영상 리포트의 성격·합격 가능성 표시를 사실 판정으로 설명하지 않는다. 실제 계정별 메뉴·문항 수·이용 시기는 실행 시 확인하도록 한다. 표절·AI 검사 외부 실습은 앞서 사용자가 보류한 범위를 유지한다. 이번 요청으로 외부 실습이나 배포를 재개하지 않았다.
