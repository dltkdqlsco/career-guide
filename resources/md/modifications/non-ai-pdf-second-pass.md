# 4개 가이드·39개 항목 PDF 2차 검토

2026-10-18. 사용자가 승인한 다음 작업(기업 분석 → 자기소개서 → IT 포트폴리오 → 면접의 정밀 대조)을 실행했다. AI 활용법과 출처·주소 입력을 제거한 정책은 유지했다.

## 대조 범위와 방법

기업 분석 10개, 자기소개서 10개, IT 포트폴리오 10개, 면접 9개의 설명·예시·작성 항목·도움말·완성 요청문을 대조했다. [1차 보고서](non-ai-pdf-first-pass.md)의 PDF 대응과 페이지 범위를 사용한다. 각 가이드에 대응하는 파일은 다음과 같다.

- 기업 분석: `resources/pdf/2-company-analysis-source.pdf` (19쪽)
- 자기소개서: `resources/pdf/3-essay-source.pdf` (36쪽)
- IT 포트폴리오: `resources/pdf/4-portfolio-source.pdf` (21쪽)
- 면접: `resources/pdf/5-interview-source.pdf` (36쪽)

현재 4개 PDF의 SHA-256이 기존 OCR·렌더링 대상과 같은지 재확인했다. 가이드별 페이지 대응과 OCR 원문으로 출력 순서·평가 기준·진행 절차를 대조하고, 기업 15쪽·자소서 30쪽·포트폴리오 9쪽·면접 19쪽의 원문 이미지를 다시 확인했다. 이번에 112쪽의 작은 화면 글씨를 모두 새로 육안 판독한 것은 아니다. 외부 서비스의 현재 계정 기능을 새로 실사한 것도 아니다.

## 저장과 검증

저장 키·백업 스키마·작성 필수 항목은 유지했다. 설명·예시·도움말·새 조합 기준을 수정했으며 사용자 저장 원문은 자동 수정하지 않는다. 수동 요청문과 의도적으로 비운 요청문도 보존한다.

- 자동 검사 **480개**, JavaScript **19개** 문법 검사, `git diff --check` 통과.
- 새 회귀 검사 8개: 상세 출력 기준의 조합 반영, 예시 필드 대응, 최종문 메모 제외, 실제 장수 우선·미실행 구분, 잘못된 문장 잔재·평가 예시, 기존 기록 보존, HTML 이스케이프 등을 검사.
- 독립 Chrome에서 1280px 화이트·390px 다크·320px 화이트로 39개 항목×3개 탭씩, 총 **351개 화면 상태** 확인.
- 각 폭에서 **39/39개 항목의 예시·작성 필드 순서 일치**. 예시 자동 입력 0, 가로 넘침 0, 페이지 오류 0. 외부 링크·출처/주소 요구가 돌아오지 않음도 확인.
- 예시 완성 요청문 복사, 실제 수동 요청문 보존·새로고침 복원, 면접 답변 변경 시 최종 확인·완료 해제, AI의 기존 묶음·입력칸 복사를 확인.
- 4개 가이드의 390px 다크 예시 화면을 시각 확인. 재현 스크립트는 `.local/checks/pdf-second-pass-browser-check.cjs`, 결과·이미지는 `/private/tmp/pdf-second-*`에 보관(둘 다 Git 제외).

실제 휴대전화·Safari·운영체제 한글 입력기·외부 계정 실습은 이번 검증에 포함하지 않았다. 배포하지 않았다.
