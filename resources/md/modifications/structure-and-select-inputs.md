# 선택형 입력과 목차 이동 개선

2026-10-19. 텍스트 정밀 검수를 후순위로 두고 사용자가 요청한 입력 방식과 목차 구조를 변경했다. AI 활용법의 작성 양식과 내용은 유지하고, 공통 목차 이동은 5개 가이드에 적용했다.

## 입력 방식

- 기업·지원 대상: 희망 직종 선택. 관련 기업 분석·포트폴리오·면접 단계에는 업종 선택, 채용 수준이 필요한 기업 분석·면접 단계에는 신입/경력/인턴/무관 선택도 제공한다.
- 자기소개서 문항: 희망 직종 선택과 기업·문항·분량의 상세 내용으로 구분한다.
- 기업 지침(1-2), 자기 분석(1-8), 포트폴리오 준비(3-0): 전공 분야·주 언어·기술 스택을 선택하고 실제 경험·역할·근거는 직접 기록한다.
- 기술 스택 정리(3-2): 기술 여러 개와 주 언어를 선택하고 기술별 사용 범위·근거는 직접 기록한다.
- 공고 기술(1-6): 실제 공고에 명시된 기술을 여러 개 선택하고 원문 맥락을 별도로 기록한다.
- 기업 도구 선택(1-1): 작업 유형과 도구 선택. 기업 지침(1-2): 결과 형식 선택. 포트폴리오 양식(3-7): 주 양식 선택.
- 모든 목록에 직접 입력을 제공한다. 기술은 선택 즉시 추가하고, 중복을 막으며, 항목별로 해제할 수 있다. 직접 입력한 기술은 추가 버튼 또는 Enter로 확정한다.
- 선택하지 않은 값을 자동 입력하지 않는다. 선택 정보는 사실·숙련도를 자동 평가하지 않는다. 실제 경험·원문·최종 답변은 자유 입력으로 유지한다.

`choice-inputs.js`는 기존 문자열 필드에 읽을 수 있는 선택 목록과 상세 내용을 함께 저장한다. 기존 키와 백업 형식을 바꾸지 않는다. 선택 정보로 명시된 형식만 파싱하며 기존 자유 글은 상세 입력에 그대로 보여 준다. 화면을 여는 것만으로 기존 값을 재작성하지 않는다. 기존 직접 수정한 요청문·빈 요청문을 덮어쓰지 않는다.

## 목차와 이동

- 상단 세부 목차를 `details`에서 항상 표시하는 `section`으로 변경했다.
- 목차 항목을 클릭하면 해당 단계만 교체하고 본문의 시작을 바로 보여 준다. 같은 목차를 다시 눌러도 본문의 시작으로 이동한다.
- 1100px 이상: 본문 오른쪽에 210px의 별도 목차 열을 두고 `position: sticky`로 스크롤 중에도 사용할 수 있게 했다. 높이가 부족하면 목차 안에서 스크롤한다. 본문 위에 겹치는 팝업 방식이 아니다.
- 1099px 이하: 본문 열을 유지하고 작은 상단 단계 선택 메뉴를 제공한다. 새 내용의 시작과 입력 포커스에 여백을 두어 메뉴 아래에 위치하도록 했다.
- 상단 목차·옆 목차의 현재 항목과 좁은 화면의 선택값이 함께 갱신된다.
- 이전·다음 단계 및 하단 탭 이동 버튼도 긴 상단 목차 대신 현재 본문 시작을 보여 준다. 일반 탭 전환의 입력·스크롤 보존은 유지한다.

## 검증

- Node 자동 검사 484개 통과. 기존 필드·예시·요청문·완료·백업 동작의 회귀 검사와 선택값의 기존 문자열 보존·왕복·입력 이스케이프 검사를 포함한다.
- JavaScript 20개 문법 검사, `git diff --check` 통과.
- Chromium 로컬 파일에서 1440/1100/1024/768/390/320px 확인. 5개 가이드·45개 단계·3개 탭, 너비별 135개씩 총 810개 화면에서 가로 넘침과 JS 오류 없음.
- 각 너비에서 기존 기록 보존, 선택·직접 입력·기술 추가/중복 방지/해제, 탭 왕복·새로고침, 직접 수정한 요청문 보존, 완료 해제 확인.
- 상단 목차 클릭과 깊이 스크롤한 위치의 옆 목차/단계 선택 후 본문 시작 위치 확인. 데스크톱 목차와 본문 사이 사각형이 겹치지 않음 확인.
- 1440px 밝은 화면과 390px 어두운 화면의 스크린샷 육안 확인. Safari와 실제 휴대전화·OS 한글 조합 입력은 이번에 별도로 검증하지 않았다.

브라우저 검증 스크립트는 `.local/checks/structure-browser-check.cjs`, 결과는 실행 환경의 `/private/tmp/structure-browser-results.json`에 있다. 배포는 수행하지 않았다.

## 카테고리 시작 위치 후속 수정

상단 카테고리 및 홈 가이드 카드 선택은 스크롤 위치를 이어받지 않고 카테고리 제목을 화면 시작 위치에 표시한다. 작성칸이나 첫 단계 본문으로 바로 건너뛰지 않는다. 이미 선택된 카테고리도 같은 방식으로 동작한다. 기존 기록은 그대로 보존한다. 브라우저 기록 API가 제한된 경우의 hashchange 대체 경로도 렌더링 완료 후 카테고리 제목으로 이동한다. 자동 검사 485개 통과, Chromium 1440/390px에서 카테고리 전환·재선택·홈 카드·기존 기록 보존 확인.

## 고정 카테고리 메뉴

로고·저장 표시 영역과 카테고리 행을 분리했다. 헤더는 스크롤되어 사라지고 카테고리 행만 위에 고정된다. 모바일에서는 메뉴를 가로로 밀어 다른 카테고리를 선택한다.

ResizeObserver로 메뉴의 실제 높이를 측정해 제목·본문·입력의 스크롤 여백과 오른쪽 목차·모바일 단계 선택 위치에 반영한다. 카테고리는 해당 제목부터 표시하며 기존 작성 기록은 유지한다.

Chromium 1440/1100/768/390/320px에서 깊은 스크롤 후 메뉴 고정, 카테고리 전환·재선택 후 제목 위치, 단계 이동 메뉴의 겹침 없음, 키보드 포커스와 가로 넘침을 확인했다. 밝은 데스크톱·어두운 모바일 화면을 육안 확인했다. 검증 스크립트는 `.local/checks/sticky-category-browser-check.cjs`에 보관했다.
