## 이번에 한 작업

- 포트폴리오 3단계 설명·가상 예시·직접 작성 화면을 활성화했다.
- 필수 작성칸 6개: 지원 직무·공고 근거·강조 방향(target), 기술 목록·분류·직접 사용 범위·자료(inventory), 숙련도 기준·중요도 범례(criteria), 기술별 중요도·숙련도·판단 이유(assessment), 포트폴리오 정리본(presentation), 미확인·수정·보완 행동(gaps).
- 핵심(Main)·보조(Sub) 구분과 직무 중요도를 먼저 정하고, 숙련도는 실제 수행 범위와 자료에 연결한다. 기술 이름·사용 기간·프로젝트 수만으로 평가하지 않는다.
- 1 기초(튜토리얼), 2 초급(예제·안내), 3 중급(문서 참고 독립 개발·검증), 4 고급(핵심 개발 주도·검토·개선), 5 전문가(리드·설계·리뷰·멘토링)의 기준을 설명 화면에 표시했다. 별도 기준을 쓰면 명시하고 0–4와 1–5를 혼용하지 않도록 안내한다.
- 중요도는 별, 숙련도는 막대로 구분하고 숫자·단계 이름·범례·판단 이유를 함께 보여주는 가상 표를 추가했다. 모바일에서는 행별 표시로 바뀐다. SQL 5/3, Java 4/2, Git 3/2처럼 중요도와 숙련도가 서로 다를 수 있음을 보여준다.
- 팀원만 사용한 Docker는 본인 숙련도를 추정하지 않고 미확인·보유 기술에서 제외로 남긴다. 학습·개발·운영, 팀 기여·본인 역할, 측정·미측정을 구분한다.
- 사용자가 작성한 정리본만 복사할 수 있다. 표시 표는 학습용 고정 예시이며 사용자 기록을 자동 채점하거나 그래프로 변환하지 않는다. 정리본과 평가 기준은 직접 작성·검토한다.
- 선택형 요청문은 target / inventory / criteria만 조합하며 평가·정리본·보완 기록·AI 원문을 이미 검토했다고 가정하지 않는다. 외부 AI 실행은 없다.
- 이전 포트폴리오 1–2단계와 기업 분석 9단계를 읽기 전용으로 참고한다. 예시·과거 기록을 자동 입력하지 않으며 기존 자유 메모·AI 원문·수동 및 빈 요청문을 보존한다.
- 필수 작성·마지막 확인 후 완료할 수 있고, 수정 시 확인·완료를 해제한다. 재조합 취소 시 보존·동의 시 재확인, JSON·Markdown 내보내기·선택 복원·직전 보호본·진행 상태를 지원한다. 포트폴리오 4단계는 준비 중으로 유지한다.

## 자료 확인 기록

`resources/pdf/4-portfolio-source.pdf` 9–10쪽을 렌더링해 시각 확인했다. 9쪽의 시각적 정리, 핵심·보조 구분·지원 직무 기술 우선 배치, 척도 선택 → 프로젝트 경험 평가 → AI 피드백의 흐름과 10쪽의 중요도·숙련도·이유 표를 반영했다.

원문에는 1–5와 0–4 두 척도가 소개되므로 이번 기본 예시는 1–5 행동 기준으로 통일했다. 특정 회사·기술·성과 사례를 사용자 사실로 취급하지 않고 SQL·Java·Git의 별도 가상 사례를 구성했다. 원문의 ‘파악 불가’ 지침을 적용해 사용 깊이가 부족한 기술을 임의로 초급 처리하지 않는다. 별·막대는 자기평가 표현이며 기업 배점·공인 능력 점수가 아니다. 자료 페이지 번호·제작 과정은 학습 화면에 넣지 않았다. 외부 사이트 작업 보류를 유지했다.
